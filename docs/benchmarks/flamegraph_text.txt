KEY OBSERVATIONS:

1. PYTHON API DOMINATES (85.68%)
   ════════════════════════════════════════════════════════════════════════════
   The vast majority of time is spent in Python C API calls, particularly:
   - Dictionary operations (creating, inserting, destroying)
   - Memory allocation/deallocation
   - Object creation (floats, lists, integers)

2. DICTIONARY OPERATIONS ARE EXPENSIVE (11.63%)
   ════════════════════════════════════════════════════════════════════════════
   Creating and managing Python dictionaries is the #1 hotspot:
   - dict_dealloc: 7.03% (cleanup)
   - PyDict_SetDefault: 1.51% (insertion)
   - dict_setdefault_ref_lock_held: 1.39%

   Optimization opportunity: Pre-size dictionaries, batch operations

3. C++ PARSING IS EFFICIENT (14.32%)
   ════════════════════════════════════════════════════════════════════════════
   Strata's C++ code is well-optimized with SIMD:
   - Structural tape collection: 2.91%
   - Whitespace skipping: 1.69%
   - Number parsing: 1.92% combined

   These are already using SIMD and are relatively fast

4. MEMORY ALLOCATION OVERHEAD (2.63%)
   ════════════════════════════════════════════════════════════════════════════
   malloc/free calls show up prominently

   Optimization opportunity: Object pooling, arena allocators

BOTTLENECK SUMMARY:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
The primary bottleneck is PYTHON OBJECT MATERIALIZATION, not parsing logic.

To match orjson's performance (2.77x improvement needed):
  1. Optimize dictionary operations (-50% = 5.8% overall improvement)
  2. Implement object pooling (-50% = 1.3% overall improvement)
  3. Pre-size data structures (-30% = 3.5% overall improvement)
  4. Optimize structural tape (-20% = 0.6% overall improvement)

  Estimated total improvement: ~11.2% (gets us to ~2.45x slower)

  Additional gains needed from more aggressive optimizations:
  - Custom dict implementation for JSON
  - String interning/caching improvements
  - Reduce Python API overhead
