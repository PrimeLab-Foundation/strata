# Framework adapters (M13, and M14's FastAPI and pydantic)

One module per framework under `python/strata/integrations/`, each filling the
framework's own JSON hook with strata's entry points and nothing else
(docs/roadmap/SKILL.md, M13 for the tier-1 five, M14 for FastAPI and
Pydantic-as-post-step; public surface: docs/context/api.md, Framework
adapters). The adapters hold no logic beyond mapping the hook's arguments onto
`strata.dumps`, `strata.dumps_with_default` and `strata.loads`; the pydantic
adapter's `default` is one `isinstance` test choosing between two pydantic
calls. Tests:
`tests/integrations/test_{flask,django,aiohttp,falcon,structlog,fastapi,pydantic_adapter}.py`
and `test_adapter_imports.py`, run by `make test-integrations` and the
`integrations` CI job, never by `make test`, `make gate` or the PGO profile
(`test_pydantic.py` beside them is the older `dumps_with_default` composition
suite, not the adapter's).

## Hook contracts, read from the installed source

Verified 2026-09-28 against Flask 3.1.3 (Werkzeug 3.1.9, Jinja2 3.1.6),
Django 6.1.1, aiohttp 3.14.3, Falcon 4.3.1, structlog 26.1.0, FastAPI 0.141.1
(Starlette 1.7.0) and pydantic 2.13.5 (pydantic-core 2.46.5). Paths below are

FastAPI and pydantic read against their own oracles, in a table of their own
(docs/decisions.md, 2026-09-28): FastAPI against Starlette's `JSONResponse`,
the class a route without `response_class` renders with, and against
pydantic's `dump_json` on a response-model route; pydantic against the model's
`model_dump_json()` and, for values outside a model, `pydantic_core.to_json`.
FastAPI's rows distinguish a route's returned value, which FastAPI passes
through `jsonable_encoder` (or `field.serialize`) before `render`, from a
returned `Response`, which reaches `render` as it is.

The two nesting rows read stdlib `json` on CPython 3.12+, whose C guard is the
C stack; on 3.10 and 3.11 it is the interpreter's recursion limit, and stdlib
fails both depths too, with `RecursionError` (500 where the framework does not
propagate it). Strata's limits are version-independent: 1024 containers when
parsing, `sys.getrecursionlimit()` when serializing (docs/context/api.md). The
`default=None` row is `dumps_with_default`'s refusal, where stdlib's
`default=None` means "no hook" and fails only on an unsupported value.

**Native types keep each framework's formatting.** From M15b,
`dumps_with_default` writes `datetime`, `date`, `time`, `UUID`, `Decimal`,
`Enum`, dataclasses, sets and numpy values itself unless the call passes
`native=False` (docs/context/api.md; docs/architecture/native_types.md,
"Opt-out"). Every adapter that hands strata a framework's `default` — Flask,
Django, structlog, pydantic — passes `native=False`, so those values reach that
`default` exactly as `json.dumps` hands them to it, and the rows above hold
for them unchanged; aiohttp, Falcon and FastAPI call plain `dumps`, whose
`native=False` default keeps the unsupported-type `TypeError` their
`json.dumps` raises. Under native precedence the suites fail nine rows — the
Flask and Django formats (HTTP date and ECMA-262 text, `Decimal` as a string,
`asdict()`), structlog's and both frameworks' chain-bound rows (a `Decimal`
returned by the hook would be written as a number), an exception from
Django's `default` for an aware `time`, and pydantic's `Z` and its
dataclass-field names — which is why none of the four follows it
(docs/decisions.md, 2026-09-29).

**Chain bound 1, and the workaround.** `dumps_with_default` does not call the
hook on its own return value; stdlib does, without limit. A `default` that
returns a `Decimal` — Django: `return o.amount` in a `StrataJSONEncoder`
subclass; Flask: the same in a provider's `default`; structlog: an
`__structlog__` returning `self.amount` — writes `"1.50"` under Django's and
Flask's defaults (`"Decimal('1.50')"` under structlog's, via `repr`) and is a
`TypeError` here. The loop belongs inside the callable, one line each:
`return super().default(o.amount)` (Django),
`return DefaultJSONProvider.default(o.amount)` (Flask),
`return str(self.amount)` (structlog). Each is a test in the framework's
module.

**Nested pydantic models never meet the chain bound.** The adapter's `default`
returns `model_dump(mode="json")`, which pydantic computes in one call for the
whole model: every field holding a model — directly, in a `list[Model]` or
`dict[str, Model]`, in a union, at any depth — comes back as JSON-native
values, so strata receives a plain dict and has nothing left to hand back to
`default` (one call per top-level model, test-pinned). A model reached through
a *native* container — a list of models, a dict whose values are models — is
an ordinary position and gets its own call. A model inside some other object
pydantic serializes (a stdlib dataclass) is dumped by `to_jsonable_python`
within that object's call, with field names even where the model's config sets
`serialize_by_alias` (the call takes a `bool`, not the config's `None`). The bound bites only a caller's own hook that
*returns* a model (`TypeError("default() returned an object of type Model that is not JSON serializable")`); the loop belongs inside the callable:
`return default(Model(...))`, not `return Model(...)`. FastAPI's adapter has no
hook; a subclass rendering `strata.dumps_with_default(content, jsonable_encoder, return_type="bytes", native=False)` gets one that never meets the bound either, since
`jsonable_encoder` returns JSON-native values.

**Where `StrataJSONResponse` pays, and where it does not.** FastAPI 0.130.0
added the `use_dump_json` path: a route with a response model and no explicit
response class is written by pydantic's `dump_json` straight to bytes, and
naming any response class — per route or as `default_response_class` — opts the
route out, to `field.serialize(mode="json")` followed by `render`. On that
path pydantic's Python-mode dump alone costs more than `dump_json` does (500
nested models, M1 under load, medians of 40: `dump_json` 656 µs,
`dump_python(mode="json")` 752 µs, plus strata 791 µs, plus Starlette's
`json.dumps` 1600 µs), so a response-model route on FastAPI 0.130+ is best left
without `response_class`. The class pays where `render` is the serializer: a
returned `StrataJSONResponse(data)` (the small tier's `mixed.json`, 30.9 KB
compact: Starlette's `render` 352 µs, strata's 33 µs), and routes without a response model, where
`jsonable_encoder` runs first (2530 µs on the same document) and strata saves
the `render` share only. Indicative screens, not benchmark rows; the adapter
docstring carries the rule.

## Version floors

The floor is the oldest release on which the adapter's suite passes on every
supported CPython (3.10–3.14), found by bisection on 3.14 (the binding end:
newer interpreters remove what old releases import) and confirmed on 3.10
(2026-09-28, CPython 3.10.20: the floors and the newest releases 3.10 allows,
Django 5.2.17 among them, both pass), which the CI `floors` leg repeats:

| Framework | Floor                  | Why not older                                                                                                                                                                                                                                                               |
| --------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Flask     | 3.0.1 (Werkzeug 3.0.0) | 3.0.0's session serializer calls `loads(value, object_hook=…)`, which the adapter refuses (ignoring it would leave tagged session values untagged); 2.2–2.3 need a Werkzeug that fails on 3.14 (`ast.Str`) or a test client that does not                                   |
| Django    | 4.1                    | 4.0 imports `cgi` and 3.2 `distutils`, both gone in 3.13/3.12                                                                                                                                                                                                               |
| aiohttp   | 3.9.0                  | 3.8.6 does not build on 3.14                                                                                                                                                                                                                                                |
| Falcon    | 4.0.0                  | 3.x does not build on 3.14 (`cgi`)                                                                                                                                                                                                                                          |
| structlog | 20.2.0                 | 20.1.0 refuses a `bytes` render (`return_type="bytes"`)                                                                                                                                                                                                                     |
| FastAPI   | 0.100.0 (httpx 0.25.1) | 0.100.0 is FastAPI's first pydantic-v2 release, and pydantic 2.12 is the oldest that runs on 3.14; the test client needs httpx 0.25.1–0.27 up to FastAPI 0.110 (0.28 removed the `app=` argument its `TestClient` passes; 0.24–0.25.0 fail on 3.14), any httpx from 0.111.0 |
| pydantic  | 2.12.0                 | 2.11's pydantic-core (2.33.2) has no 3.14 wheel and does not build there                                                                                                                                                                                                    |

`pyproject.toml`'s `integrations` extra carries these as `>=` floors; the CI
`floors` leg installs them exactly on Python 3.10, the `latest` leg the newest
releases on 3.14.
