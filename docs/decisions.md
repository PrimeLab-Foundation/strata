# Decision Log

One line per decision. Append-only; never edit past entries — supersede with
a new line. Format: `date · area · decision (and the rejected alternative when it clarifies)`. Anything ambiguous during implementation gets decided
*here*, visibly — never silently in code.

- 2026-08-09 · build · `cpp_tests.py` passes `--config`/`--build-config` and resolves cmake/ctest beside `sys.executable` before PATH, so multi-config generators do not silently fall back to Debug and `make gate`'s two drivers cannot configure one build tree with two different CMake binaries.
- 2026-08-09 · build · `cmake>=3.20` is a `dev` extra: `make test` drives ctest, so the documented `make dev && make test` path must not depend on a system CMake that no make target can install.
- 2026-08-09 · build · Open for M1: C++ test binaries compile without `-march=native` while the extension compiles with it, so SIMD paths would be tested under different flags than they ship with. Decide flag parity (mirror the extension flags, or register two configurations) before the first SIMD source lands.
- 2026-08-09 · core · `Result::unwrap()`, `Result::value_or()` and `FlatMap::count()` are not rebuilt: all three had zero callers anywhere in the previous implementation, which checked `ok()` and read `value` directly. Add them when a caller exists (rejected: porting the blueprint header verbatim, dead API included).
- 2026-08-09 · core · `Result` gives both members default initialisers and `ok()` is `constexpr`, so a Result built without a value holds a default-constructed `T` instead of an indeterminate one; the guarantee is pinned by a `consteval` check, because the equivalent runtime assertion would be reading uninitialised memory that usually happens to be zero.
- 2026-08-09 · core · `FlatMap::emplace()` keeps the blueprint's append-without-duplicate-check behaviour, now stated as an explicit caller contract and pinned by test: `find()` returns the first match, and the parser's duplicate-key policy is built on exactly that.
- 2026-08-09 · core · Core purity is enforced by `tests/unit/test_core_purity.py` (scans `include/` + `src/strata/` minus `bindings/`, with a positive control so it cannot pass vacuously); core files avoid naming the CPython header even in prose so the roadmap's documented grep stays literally empty.
- 2026-08-09 · build · Supersedes the M1 obligation logged above: M1 added no core `.cpp` (the value model is header-only), so the single shared C++ source-list definition is due at M2, before the first core translation unit.
- 2026-08-09 · parse · SAX gains `on_big_int(std::string_view)` carrying the raw token, so integers beyond int64 reach handlers exactly; `on_uint` and the `size_hint` parameters are not rebuilt (never emitted / always 0). The previous implementation accumulated only the first 19 digits and returned that truncation as the value.
- 2026-08-09 · parse · Number conversion uses `std::from_chars` — correctly rounded and locale-independent — instead of the blueprint's Clinger fast path plus `strtod`, whose result depends on the process locale's decimal separator. The fast path may return at M5 with a benchmark behind it.
- 2026-08-09 · parse · Values outside the double range saturate to ±inf / 0 like stdlib `json`, rather than failing the parse (`1e400`, `1e-400`).
- 2026-08-09 · parse · A leading UTF-8 BOM is rejected: it is not part of a JSON text (rejected: stdlib's behaviour of stripping it from bytes input). Found by oracle-diffing against `json.loads`; pinned by test alongside the other deliberate divergences (NaN/Infinity, escaped lone surrogates, CESU-8 surrogates).
- 2026-08-09 · parse · Scan primitives live in `include/strata/util/scan.hpp` as `validate_utf8`/`skip_whitespace`/`find_next_escape`, named for what they do rather than how; vectorised bodies replace them at M5 behind the same names (rejected: the blueprint's `simd_*` names, which already described scalar code).
- 2026-08-09 · parse · M2 ships the parser scalar and without the speculative-key hook or the inline array fast path; both are performance work for M5, where a benchmark can justify them.
- 2026-08-09 · parse · The duplicate-key policy (enum, thread-local setting, warning list) lands with the DOM builder, which cannot avoid choosing a behaviour; wiring it to `strata.config` stays in M4.
- 2026-08-09 · build · Core translation units are enumerated once in `src/strata/core_sources.txt`, read by CMakeLists.txt and setup.py, and pinned by a contract test. The file is ASCII-only because CMake's `file(STRINGS)` treats non-ASCII bytes as separators and silently splits comment lines into bogus entries. This discharges the shared-source-list obligation logged for M2.
- 2026-08-09 · build · Fuzz targets are opt-in (`-DFUZZ=ON`) and fail *configure* with an actionable message when the toolchain has no libFuzzer runtime — Apple's clang never ships one, so the blueprint's raw "libclang_rt.fuzzer_osx.a not found" link error was the first sign. Seed corpus and scheduled runs stay at M9.
- 2026-08-09 · serialize · dtoa is built on `std::to_chars` (shortest, correctly rounded) rather than vendoring reference Dragonbox + fast_float. M3's acceptance criteria are correctness only, the archive note describes that salvage as a measured *dumps throughput* win, and fast_float's job (text to double) is already covered by `std::from_chars`. Vendoring stays an M5 candidate, to be justified by a benchmark (rejected: vendoring now, before any measurement).
- 2026-08-09 · serialize · Floats render exactly as CPython's `repr`: fixed notation while the decimal point sits in (-4, 16\], scientific outside it, always with a fraction. Verified over 152,640 doubles with zero divergence and zero round-trip failures (rejected: orjson's plain shortest-scientific, which would print `1e+15` where stdlib `json` prints `1000000000000000.0`).
- 2026-08-09 · serialize · One converter, `util::format_double` in `util/dtoa.hpp`, named for its output rather than an algorithm; the previous implementation carried three overlapping converters whose names had come loose from their contents (a "dragonbox" that was Ryu, a "ryu" that wrapped `to_chars`, and a dead `fast_dtoa`).
- 2026-08-09 · serialize · NaN and infinity map to `null` in the serializer, not in the converter: what to emit for a value JSON cannot spell is a serialization policy, and `format_double` is never handed one.
- 2026-08-09 · serialize · Output escapes only what RFC 8259 requires — quote, backslash, the five short escapes, and remaining bytes below 0x20 as lowercase `\u00xx`. UTF-8 passes through as bytes, `/` is never escaped, and 0x7f is not a control character.
- 2026-08-09 · build · `OutputBuffer` and its `unsafe_*` writes are not part of M3: they exist to make the *Python* `dumps` path allocation-free and belong with the binding and performance milestones.
- 2026-08-09 · bindings · `return_type="cursor"` and `iterator=True` raise `NotImplementedError` until the milestones that build them, per convention rule 1 (a capability absent from C++ is not faked in Python). Contract tests pin the refusal now; the behavioural tests land with the feature (rejected: `ValueError`, which api.md reserves for an *unknown* `return_type`).
- 2026-08-09 · bindings · `loads` runs the up-front UTF-8 pass for `bytes` only. A `str` is already valid Unicode, so its encoded form needs no re-check; for `bytes` the parser is the only validator there is (docs/context/api.md).
- 2026-08-09 · bindings · A `str` holding lone surrogates cannot be encoded to UTF-8; `loads` reports that as `ValueError("Invalid JSON")` rather than letting a `UnicodeEncodeError` escape, since the argument is not valid JSON text either way.
- 2026-08-09 · bindings · Cycle detection runs under every policy, including `"ignore"`: api.md requires `"ignore"` to emit `null` silently, which is impossible without detecting the cycle. The previous implementation skipped tracking under `ignore`, so a cycle recursed until the depth ceiling and raised instead.
- 2026-08-09 · bindings · The duplicate-key `"error"` policy surfaces as `ValueError("Invalid JSON")` — it is a parse failure, and api.md pins that message for parse failures. Cycle errors under `cycle_policy="error"` raise `ValueError("Circular reference detected")`; api.md pins the depth message verbatim but leaves this one open.
- 2026-08-09 · bindings · `config.get`/`config.list` read the live policy variables instead of a cached map, so what is reported and what is in force cannot drift apart — this is the structural fix for the previous implementation's `cycle_policy` bug, not just a corrected initial value.
- 2026-08-09 · bindings · Binding-internal declarations (`loads_to_python`, `dumps_to_python`, the cycle policy) live in `python_types.h`, the layer's existing shared header, rather than a second one.
- 2026-08-09 · serialize · `append_escaped_json_string` is promoted to the core's public surface so the binding layer escapes Python strings against the same table as the C++ serializer, rather than carrying a second copy of it.
- 2026-08-09 · tests · "Mirrored" tests are read as *the same behaviours covered on both sides*, not byte-identical files: `tests/unit` holds the clause-by-clause contract suite, `tests/py` exercises the same surface end to end against the stdlib `json` oracle. The previous implementation's byte-identical mirrors are recorded as having drifted apart (docs/build-and-test/SKILL.md).
- 2026-08-09 · bench · Benchmarks measure the libraries **interleaved**, one round each, rather than all repeats of one library before the next. Measured during M5: the sequential order let heap growth and cache state land on whichever library ran late, reporting orjson as 4x slower on one dataset than it was in isolation. The harness fix changed the numbers, so the baseline was recaptured after it.
- 2026-08-09 · bench · The report format lives in `benchmarks/harness.py` and both the writer (`render_report`) and the gate's parser (`parse_report`) go through it; baselines are keyed by the full report filename. The previous checker parsed a heading the writer no longer emitted and keyed on a stem, so it silently compared nothing.
- 2026-08-09 · bench · The regression gate enforces the contract's thresholds — >2% median, >2% p95, >5% RSS — and its `main()` is covered end to end by tests through argv and exit codes, including the "no strata rows found" case that made the previous tool useless.
- 2026-08-09 · bench · M5 benchmarks only the categories that exist (`loads`, `dumps`); file, folder and JSONPath sections join with their milestones rather than being stubbed as empty tables.
- 2026-08-09 · perf · No module-lifetime small-int cache: CPython already caches small integers, so the blueprint's 0..256 cache duplicated one that exists. Presized dicts via `_PyDict_NewPresized` are deferred — the API is CPython-internal and version-sensitive, and nothing has yet measured what it is worth here.
- 2026-08-09 · perf · After M5 the rebuild is #3 of five on most categories: `loads` 1.16-1.63x behind orjson, `dumps` 2.4-3.9x behind. Recorded rather than smoothed over — the previous implementation led those categories, and the gap is the un-rebuilt dumps fast paths.
- 2026-08-09 · cursor · A Python cursor holds a `shared_ptr` share of the parsed tree rather than a reference to a separate document object. The document-outlives-cursor invariant then holds by construction, no document type is exposed, and the facade stays logic-free (rejected: the previous implementation's `(document, cursor)` tuple that the facade had to re-assemble).
- 2026-08-09 · cursor · Cursor mode is DOM-backed, so its numbers are doubles and large integers lose precision there, while `loads` keeps them exact. The asymmetry is inherited from the C++ value model and is now pinned by test rather than left to be discovered.
- 2026-08-09 · cursor · `at()` accepts negative indices, counting from the end as Python does everywhere else; out of range either way raises `RuntimeError("index out of range")`.
- 2026-08-09 · ndjson · Records are parsed straight to Python objects line by line, never through the C++ DOM: routing them through it would round integers through a double and break the exactness contract for NDJSON.
- 2026-08-09 · ndjson · The iterator form is genuinely lazy — a dedicated iterator type owns the file text and parses on each `__next__` — so a malformed line raises when iteration reaches it, as api.md describes. Returning `iter(eager_list)` would have reported the failure before iteration began.
- 2026-08-09 · ndjson · Blank and whitespace-only lines are separators, not records, and are skipped without counting as errors; `\r\n` endings and a missing final newline are both accepted.
- 2026-08-09 · files · `dump` chmods the file to 0644 after writing on POSIX: `fopen` alone would leave the mode to the process umask, and api.md states the mode.
- 2026-08-09 · files · `split_by` with a file target raises `ValueError` now, which is both the documented behaviour and what folder mode will need; the directory form arrives with the folder milestone.
- 2026-08-09 · files · A malformed NDJSON line reports which line failed (`Invalid JSON on line N`). api.md pins `ValueError` for parse failures but not the text, and a bare "Invalid JSON" is close to useless for a file of thousands of records.
- 2026-08-09 · jsonpath · `search(f, e)` is *defined* as `query(load(f), e)` rather than implemented separately. The milestone requires the two to agree for every supported expression, and two implementations kept in step by testing is exactly how the previous one drifted; defining one in terms of the other makes the law unfalsifiable by construction.
- 2026-08-09 · jsonpath · Recursive descent descends into its own matches, so `$..a` returns an `a` nested inside an `a`. That is query semantics, which the milestone names as the winner of the previous SAX-vs-DOM divergence, and both evaluators implement it.
- 2026-08-09 · jsonpath · **The SAX streaming evaluator is not built.** `is_streamable()` exists and excludes Slice, Filter *and* RecursiveDescent — the last because a streaming matcher that captures a subtree must keep searching inside it, which is precisely where the previous implementation broke the law. Streaming is a throughput feature (the docs call it the headline perf win), so it lands with a benchmark behind it rather than at the cost of correctness.
- 2026-08-09 · jsonpath · A step after a filter applies to each matched node, not to the list of matches, so `[?(...)][0]` indexes into every matched object rather than taking the first match. Standard node-list semantics; pinned by test because it surprises.
- 2026-08-09 · jsonpath · Filter comparisons treat Python `bool` as not-a-number, matching the C++ DOM evaluator. The previous implementation coerced bools to 1.0/0.0 in the PyObject path only, so `query()` and `CompiledPath.execute()` could disagree.
- 2026-08-09 · jsonpath · `CompiledPath.execute(cursor)` returns cursors, each sharing the document, so results stay lazy and cannot dangle.
- 2026-08-09 · jsonpath · The `.json`/`.ndjson`/`.jsonl` extension check for `search()` lives in the facade, where the `Path` normalization already is; it is a `TypeError` about the argument, not a parse failure.
- 2026-08-09 · folder · Discovery lives in one core routine that both folder `load` and folder `search` call, which is what makes the folder-search law hold rather than something two code paths have to agree on.
- 2026-08-09 · folder · "Symlinks not followed" is read as *skip every symlink*, file or directory, not merely "do not descend". A symlinked file is followed too when it is opened, and the stricter reading also makes a symlink loop impossible (verified by test).
- 2026-08-09 · folder · Hidden means a leading dot on an entry met during traversal; the directory the caller names is never itself pruned. A hidden directory's whole subtree is excluded, visible files included.
- 2026-08-09 · folder · A split value that is not `str`/`int`/`bool` raises `TypeError`, not `ValueError`: api.md's ValueError list covers a missing key and an unsafe name, and the error contract says a wrong value type is a `TypeError`.
- 2026-08-09 · folder · Collision detection is scoped per key level. The same text at two different levels names two different path components and cannot collide on disk, so `{"a": 1, "b": "1"}` with `split_by=["a","b"]` is `1/1.json`, not an error.
- 2026-08-09 · folder · Case-only collisions are rejected on every platform, not only case-insensitive ones: the parenthetical in api.md is the motivation, and a platform-dependent exception could not be tested in CI.
- 2026-08-09 · folder · `dump` groups and validates the whole input before writing anything, so a record that fails validation leaves no partial output behind (pinned by test).
- 2026-08-09 · folder · `dump` picks folder mode when the target is an existing directory, or when it does not exist yet and `split_by` was given — api.md has `dump` create `dirpath`, so the target need not exist. `split_by` is therefore an error only against a target that already exists as a file, which is what "a file path" can be checked to mean.
- 2026-08-09 · folder · Folder `load` and `search` with `iterator=True` stream file by file through a dedicated iterator type: a directory can hold more than fits in memory, and a malformed file should surface when iteration reaches it. Discovery itself stays eager so a missing directory raises at the call.
- 2026-08-09 · folder · Folder `search` compiles the expression once and reuses it for every discovered file. It has no `skip_errors` parameter, so a malformed file aborts it — the documented equivalence to running `search` per file leaves no room for silently skipping one.
- 2026-08-09 · ci · The M0 CI skeleton is three test legs (ubuntu 3.10/3.14, macOS 3.12) plus a style job, on `*-latest` runner labels (rejected: the blueprint's eight-leg matrix on pinned 2022–2024 images); the full matrix is M9.
- 2026-08-09 · fuzzing · The committed corpus is replayed by a ctest suite (`tests/cpp/test_fuzz_corpus.cpp`), including every truncation and single-byte mutation of each seed. libFuzzer needs a runtime Apple's clang does not ship, so without this the corpus would be exercised only by a weekly Linux job — and the reason the previous corpus never existed is precisely that nothing local depended on it.
- 2026-08-09 · fuzzing · Seed intent is encoded in the file name: `bad_*` (and `empty`) must be rejected, every other seed must parse. A seed whose meaning silently changes then fails the build instead of quietly weakening the corpus.
- 2026-08-09 · fuzzing · `make fuzz` on stock macOS stops at the configure-time probe with an actionable message rather than falling back to a non-fuzzing build. The literal M9 criterion "fuzz runs locally for FUZZ_TIME" is therefore unverified on this machine; it needs `brew install llvm`, which is a machine-wide change left to the human.
- 2026-08-09 · coverage · C++ coverage instruments the single CMake registry via `-DCOVERAGE=ON`, and llvm-cov is given every suite binary plus an explicit source list. One registry means no second list to drift; the explicit source list keeps libc++ headers out of the percentages.
- 2026-08-09 · coverage · `make gate` gained a coverage step. `GATE_SKIP_COVERAGE=1` skips it for iteration — the step reports numbers rather than deciding pass/fail, so unlike `SKIP_TESTS` it is not an escape hatch around a gate.
- 2026-08-09 · testing · Added `tests/cpp/test_folder.cpp`. Coverage showed `src/strata/util/folder.cpp` at 0% from the C++ side: folder mode arrived at M8 with Python tests only, which the cross-layer parity rule forbids. C++ coverage went 87.7% → 93.9%.
- 2026-08-09 · pgo · PGO uses **IR-level** instrumentation (`-fprofile-generate` / `-fprofile-use`), not the front-end kind (`-fprofile-instr-*`) the blueprint used. Front-end counters are source-level and map poorly onto post-inlining IR: measured here they made the optimized build ~20% *slower* than plain `-O3`. IR-level is 8–12% faster on loads and 11–25% on dumps.
- 2026-08-09 · benchmarks · The report's `compiler_flags` line is now derived from the environment instead of hardcoded, so a PGO+LTO run cannot be filed under plain `-O3` and silently compared against one.
- 2026-08-09 · ci · The full matrix is ubuntu 3.10–3.14 plus macos-13 (x86_64), macos-latest (arm64) and windows-latest on 3.12, plus coverage, style, and an ASan+UBSan corpus-replay job on every push. Windows and macos-13 are unverified locally — no such machine here — so their first real run is on push.
- 2026-08-09 · dtoa · `format_double` asks `to_chars` for the *fixed* shortest form directly instead of taking the scientific form and re-laying out its digits. Python's fixed-vs-scientific rule is a pure magnitude test (1e-4 \<= |v| \< 1e16), and the boundaries are themselves representable, so no value can round across one. 77.8 -> 41.2 ns/value, verified byte-identical to `repr` over 900k doubles spanning the whole bit space.
- 2026-08-09 · dtoa · Whether to append `.0` is asked of the value (`v == trunc(v)`), not of the emitted digits: shortest-fixed omits the point exactly when the value is integral. Replaces a `memchr` over the output.
- 2026-08-09 · dumps · Arrays of one scalar type (int/float/bool) format through a stack chunk, one buffer append per 64 elements. The element type is re-checked on every element and a mixed list simply ends the run early, so the fast path can never emit bytes the general path would not.
- 2026-08-09 · dumps · The scalar-run chunk is a member of the serializer, not a local. `write_sequence` recurses, and a 2.5 KB array on every frame made deeply nested documents overflow the C stack (caught by the deep-nesting tests).
- 2026-08-09 · dumps · Prepared `"key":` bytes are cached **per nesting depth**, not per serializer. A single slot thrashes on real documents, where a record's children have their own shapes; and per-depth slots also remove the reentrancy hazard, since a nested object can no longer overwrite the slot its parent is mid-way through reading.
- 2026-08-09 · dumps · A schema is prepared on its *second* sighting at a depth. Preparing costs about what writing costs, so documents made of one-off shapes were paying for a cache they never used (mixed.json regressed 20% until this was added).
- 2026-08-09 · scan · `find_next_escape` is SIMD (NEON/SSE2) with `find_next_escape_scalar` kept as its twin and exported so `tests/cpp/test_scan.cpp` can run the two against each other over every alignment, every byte value and a match at every lane. The styleguide requires the twin; this makes the requirement checkable rather than asserted. The previous implementation's masked-load trick read past the end of short strings and is deliberately not reproduced.
- 2026-08-09 · benchmarks · The harness now covers every category the contract names (`load`, `load (ndjson)`, `dump`, `query`, `search`) and `render_report` fails on a measurement in a section missing from `SECTIONS` — previously such rows were silently dropped while still counting as errors.
- 2026-08-09 · benchmarks · Query and search rows are checked for *equal result sets* before timing, and a library computing something different is excluded with the reason recorded. jmespath's `[*]` projects where `[]` flattens; the projecting spelling returned 1000 nested lists against the others' 4994 values and would have timed as a win.
