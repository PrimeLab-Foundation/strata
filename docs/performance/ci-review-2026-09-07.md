**Review findings, in execution order**

1. **High: reentrant serialization leaks the private schema cache's owned keys.**

   [python_dumps_output.h](../../src/strata/bindings/python_dumps_output.h)
   `Schema::remember` at line 318 takes references to keys. A reentrant call
   allocates `fallback_` at line 503. `~SchemaCacheLease` at line 507 only
   releases the shared busy flag; destroying the private `State` destroys
   vectors of raw `PyObject*` without releasing their owned Python references.
   Neither `State` nor `Schema` supplies the missing cleanup.

   On the installed CPython 3.14.7 extension, 100 reentrant calls increased
   a dynamic exact-string key's reference count from **4 to 104**. After
   warming an ordinary call with the same dictionary, 100 ordinary calls
   held its count at **105**. The extension's MD5 is
   `4bca2d1d0e6204d276b88b2c93027dc0`, matching the recomposed published
   build recorded in E26-P5. The following reproduces the growing reference
   count in a disposable interpreter:

   ```python
   import sys
   import strata

   key = "".join(["review-", "dynamic-", str(id(object()))])
   inner = {key: 1}

   class ReentrantInt(int):
       def __str__(self):
           strata.dumps(inner, return_type="bytes")
           return "1208925819614629174706176"

   outer = [ReentrantInt(1 << 80)]
   strata.dumps(outer, return_type="bytes")
   before = sys.getrefcount(key)
   for _ in range(100):
       strata.dumps(outer, return_type="bytes")
   print(sys.getrefcount(key) - before)  # observed: 100
   ```

   Fix private-state ownership on successful and exceptional exits. Keep
   the shared cache's documented interpreter-shutdown policy explicit.
   Adding a destructor to an owning `Schema` also changes its implicit move
   behavior: audit vector relocation and copying so a leak fix cannot become
   a double decrement. The existing reentrancy tests cover object lifetimes
   extensively, but do not catch this private-cache key leak.

2. **High: incomplete or non-finite benchmark data can produce a passing gate.**

   [supportability_check.py](../../benchmarks/supportability_check.py) checks
   only sections that have surviving measurements. It does not require
   Strata in every dataset row, an expected set of categories, or any rows
   at all. [ci_summary.py](../../benchmarks/ci_summary.py), lines 55 and 100,
   similarly ranks the comparable subset and derives the goal denominator
   from the reports it received. Missing rows and platforms can disappear
   from the objective.

   Temporary-fixture reproductions returned:

   | Input defect | Observed result |
   | --- | --- |
   | Empty report | Exit 0: `supportability: 0 rows within 3.0x, no ERROR rows`. |
   | Two datasets in one section, one lacking Strata | Exit 0: two rows reported within the bound. |
   | One passing comparable row, other evidence missing | Summary: `Goal met on 1/1 platforms.` |
   | Strata median `nan` | Tripwire exits 0; summary assigns rank 1. |
   | `run_info.json` claims a different SHA and report map | Summary CLI exits 0. |

   [harness.py](../../benchmarks/harness.py), lines 267–325, silently ignores
   malformed table rows and accepts `float("nan")`. Thus “no ERROR rows” is
   insufficient validation. Introduce a shared validity and completeness
   check with an explicit expected workload/platform manifest. Keep legitimate
   diagnostic subsets and unsupported competitors representable, but identify
   them as scoped evidence rather than a complete goal result. Preserve the
   intentionally loose 3.0x supportability bound.

3. **High: the regression checker succeeds when it compares no baseline entries.**

   [regression_check.py](../../benchmarks/regression_check.py), lines 70 and
   145, skips unmatched keys and reports success if no breach was collected.
   A temporary report containing one valid Strata row and a nonempty baseline
   keyed under a different report filename produced exit 0 and:

   ```text
   compared 0 of 1 entries against baseline.json
   no regressions
   ```

   Require nonzero coverage and complete coverage of the declared comparison
   scope, including required metrics. Missing current rows must also be
   detected; iterating only current entries cannot find their disappearance.
   Report new, unmatched categories explicitly. Preserve the full-filename
   key contract and the >2% median/p95 and >5% RSS thresholds.

4. **High for performance decisions: the A/B effect and its quoted uncertainty
   are calculated by different estimators.**

   The experimental [ab_blocks.py](../../benchmarks/ab_blocks.py), line 60,
   computes a median of effects from ABBA block means, after normalizing
   each launch by its in-process rival. [ab_floor.py](../../benchmarks/ab_floor.py),
   line 98, instead bootstraps paired individual launch values and reports a
   ratio of medians. Its interval is not an interval for the block statistic.
   The E26-P6 reading rule currently combines them.

   There is a second concrete omission: `ab_floor.py` defaults to
   `--rival orjson-bytes`, while `loads` rows contain `orjson-loads`.
   The workflow's default invocation therefore emits no normalized `loads`
   floor. `ab_blocks.py` prints the normalized `loads` effect, but supplies
   no matching interval. It also treats every non-A build as B, so adding a
   third arm would silently pool candidates.

   Use one validated analysis implementation for the effect, interval, and
   A/A control. Preserve ABBA blocks as the resampling unit. Validate order,
   build labels, row coverage, and sample counts; select the rival per
   operation. Display raw Strata and rival changes alongside normalization:
   a rival's movement need not be pure host drift when both engines share
   process and allocator state.

5. **Medium: the diagnostic driver can lose evidence, leave another binary
   installed, and cannot yet cover the required Windows/file cases.**

   [ab_rows.py](../../benchmarks/ab_rows.py), lines 55–81, replaces the
   extension at each launch and writes its accumulated TSV only after all
   launches succeed. There is no restoration in `finally`; a successful run
   with the default trailing A leaves A installed. A failed later launch
   loses earlier captured samples. [ab_builds.py](../../benchmarks/ab_builds.py)
   has the same shape.

   [rows_probe.py](../../benchmarks/rows_probe.py), line 77, unconditionally
   calls Unix-only `os.getloadavg()` when the driver passes `--identify`.
   Its operation dispatch supports only `loads` and `dumps`. It cannot supply
   the `load`, NDJSON `load`, or `dump` evidence requested in the ledger.

   The experimental [ab_x86.yml](../../.github/workflows/ab_x86.yml) profile
   loop calls `strata.dumps(doc)` without `return_type="bytes"`; the public
   default is text, while CI's `dumps` row measures bytes. Correct the
   profile target before using it to explain that row. Persist completed
   samples incrementally, restore the original extension on failure and
   success, label unavailable counters explicitly, and support the real file
   operations before relying on the driver for those gates.

6. **Medium: canonical reports cannot identify the measured binary or recover
   the timing distribution.**

   [bench_main.py](../../benchmarks/bench_main.py), line 45, constructs
   `compiler_flags` from environment variables at report time. This is not
   build provenance. For example, the Windows report says `/O2`, while
   [setup.py](../../setup.py), line 371, adds the effective `/clang:-O3`
   override. Linux's actual ThinLTO and function-splitting flags are also
   lost in the simplified description. The commit is `git rev-parse HEAD`
   without dirty-state identification, and Linux's processor field is only
   `x86_64` or `aarch64` in the supplied reports.

   Compiler versions, extension hashes, dependency versions, dataset hashes,
   and PGO profile identities are absent. Raw timing arrays are discarded
   when rows are summarized. Add a versioned sidecar with those identities,
   full-precision samples, explicit exclusions, and protocol parameters;
   retain the readable Markdown view and preserve historical report support.
   Capture metadata outside the timed calls.

7. **Confirmed on one host: the safe serializer has an x86 performance cost
   that warrants targeted work. Its mechanism remains a hypothesis.**

   The new [E26-P6 run](https://github.com/PrimeLab-Foundation/strata/actions/runs/34065637472)
   built both revisions on an AMD EPYC 9V74 host with four vCPUs. Its local
   artifacts are under `build/evidence/E26-P6/run_34065637472/`.
   Arm A is `32c5fa4`, MD5 `a9d5a90eb07f85993b02a06f3528dc28`; arm B is
   `93799cd` with the `79fa3df` runtime source, MD5
   `00ac9ccfb01aaab1ef825824902e1156`.

   Independently recomputing the complete ABBA blocks from `R1.tsv` gives:

   | Bytes-mode row | Median normalized B/A change | Six block effects, min to max | Same-binary A/A block effects |
   | --- | --- | --- | --- |
   | Small `dumps wide_arrays` | +7.008% | +6.211% to +7.788% | -0.053%, +0.155% |
   | Small `dumps flat` | +3.611% | +2.514% to +4.551% | +1.044%, +0.217% |
   | Medium `dumps flat` | +3.978% | +2.576% to +5.294% | +0.104%, -0.512% |
   | Small `dumps mixed` | +0.738% | -0.397% to +1.700% | +0.286%, +0.792% |
   | Small `loads wide_arrays` control | -0.068% | -1.106% to +1.673% | +0.143%, +0.584% |

   These are descriptive block results, not the mismatched confidence
   intervals discussed in finding 4. There are only two A/A blocks, using
   one identical artifact; they do not measure fresh-build/profile variance.
   The wide-array and flat costs are substantially larger than that observed
   timing variation. The small mixed effect is unresolved.

   [python_dumps.cpp](../../src/strata/bindings/python_dumps.cpp), lines
   337–404, refreshes list storage after every general-loop element for
   mutation safety. Lines 774 and 1012 re-index movable schema storage;
   lines 1248–1323 maintain row ownership. These are reasonable targets for
   attribution. The local `build/evidence/E26-P6/CODEGEN.md` proposes reducing
   list refreshes and stabilizing schema addresses, but its assembly is an
   Apple-clang cross-compilation without PGO or LTO. It cannot establish the
   Linux/Windows production mechanism. The native PGO frames actually shrank
   while these rows slowed. Do not accept frame size or fewer static spills
   as a speed result.

   Preserve the `79fa3df` use-after-free and surrogate-key fixes. The old
   unsafe revision is useful only as an attribution reference. Any epoch or
   mutation-witness design needs a proof covering all callbacks, reference
   releases, nested calls, and counter overflow. A fixed 65-depth schema
   allocation proposed in the static note would also grow per-thread state
   by roughly 182 KB; consider its allocation and retention cost explicitly.

8. **Medium: first-place rows can still lose margin through PGO changes.**

   Recomputing the macOS ARM64 reports against the `32c5fa4` snapshot gives
   `loads wide_arrays` ratios of 0.7983 before and 0.8461/0.8391 afterward;
   `load wide_arrays` 0.8005 to 0.8437/0.8419; `load users` 0.6552 to
   0.7123/0.7103. These remain first, but their relative margins shrink in
   both draws. The machines/sessions differ, so this is an investigation
   signal, not a measured source regression.

   [pgo_build.sh](../../scripts/pgo_build.sh), lines 70–110, merges profiles
   from the instrumented test gates as well as the dedicated workload.
   Additional tests can therefore change parser layout even when parser
   source is unchanged. Record profile composition and include these parse
   and file-load rows in a same-host comparison. The older training-only
   recipe was already rejected on the fixed source: E26-P5b measured
   +3.3–6.3% on serializer rows and +1.5–1.7% on `loads wide_arrays`.
   That negative result remains applicable.

9. **Medium: file-write tails and extra semantics need separate attribution.**

   In the supplied Linux x86 report, `dump mixed` has median **0.119 ms** and
   p95 **98.331 ms**; Linux ARM64 `dump users` is **2.591 / 13.602 ms**.
   [harness.summarize](../../benchmarks/harness.py), line 127, selects the
   maximum sample as p95 when there are ten repeats. These observations
   establish instability in that run, not its cause. Save samples, measure
   tails in controlled windows, and retain unfavorable draws.

   [python_files.cpp](../../src/strata/bindings/python_files.cpp), line 224,
   serializes to bytes and writes the file. POSIX uses `writev` for JSON plus
   newline and checks mode 0644; Windows writes the newline in a separate
   `_write`. The rivals' composition does not add Strata's documented
   newline or enforce its POSIX mode. Those observable guarantees must stay.
   Profile serialization, open/truncate, writing, metadata, and close with
   real files. Subtracting separately measured `dumps` and `dump` medians
   does not isolate the I/O cost.

10. **Medium: fetching reports is not transactional despite its contract.**

    [ci_fetch._place](../../benchmarks/ci_fetch.py), line 111, removes the
    previous reports and metadata before writing replacements. Injecting
    an `OSError` on the second report write left only the first new report;
    the previous evidence and `run_info.json` were gone. Stage the entire
    validated replacement and preserve the prior snapshot if installation
    fails. Fetch validation must also verify run/report identity and expected
    coverage; parsing an OS/architecture header alone is insufficient.

11. **Scope limitation: 135/135 covers one tier, Python version, and selected
    operations. Broader coverage needs its own denominator.**

    [benchmark.yml](../../.github/workflows/benchmark.yml) runs the small tier
    on CPython 3.12. [bench_main.run](../../benchmarks/bench_main.py), line
    351, continues immediately after NDJSON `load`; NDJSON `search` from the
    benchmark contract is absent. Folder comparisons against a Strata
    per-file loop are also outside these 27 rows. Medium/large validation
    and those feature comparisons cannot be inferred from this tracker.

    [ci.yml](../../.github/workflows/ci.yml) tests Python 3.10–3.14 on Linux
    x86, and Python 3.12 on the other four platform/architecture combinations.
    It does not test every OS/architecture/Python combination. Extend relevant
    version endpoints when CPython internals change, and schedule broader
    coverage separately from the current ranking objective. Keep old and
    expanded benchmark scopes distinguishable.

**What to retain from previous work**

The [experiment ledger](experiment-ledger.md) and
[performance guidance](SKILL.md) supersede the September 6 draft's ordering.
Cycle-stack allocation was attributed at about 150 ns, roughly 0.3% of the
target and below its measured A/A resolution; the inline-prefix prototype
was rejected before implementation. Broad cold-code splits, write-frame
splits, and the wide-integer rewrite failed prior acceptance checks. The
training-only PGO change loses on the current fixed source. Reopening one
requires new evidence explaining why that result no longer applies.

Keep the parser's value-cursor gains, the 1024-container parsing cap, raw-dict
runtime proof, exact-string-only schema keys, isolated reentrant leases,
latched ownership, failed-schema invalidation, and file output semantics.
The serializer's recursion-limit contract is separate from the parser cap.
